Why Momentum is tested the way it is

Momentum is a pre-release product preview. This page explains what our testing is for and what it has taught us. It is not a list of finished features; the home page says what the current command-line tool does and does not do.

The problem with AI-written programs

Asking an AI to write a program is easy. Knowing the program works is the hard part. It can look right, compile, and still fail on the awkward inputs: an empty value, a stray tab, a Windows line ending. It can also quietly do something you never agreed to.

Momentum is designed around that gap. You describe what you want, and the intended workflow has an AI generate the program, build it, test it and repair it in a loop, with guards and your consent before anything changes. A loop like that is only worth trusting if it has been pushed hard first, and that is what our testing is for.

How we test it

For each language Momentum supports, we run the same kind of trial a user would trigger. A local model is given a task and writes the code, and the code is built and run. We then score it with a checker the model never sees, so it can't pass by guessing what we look for.

We repeat this many times per language, because one lucky run proves nothing. We record how often the result is right, how long it takes and how fast the model works on ordinary hardware. The exact method, briefs and terms are on How we test.

What a failure gives us

A failed trial is useful. We read why it failed and change something in Momentum:

  • Clearer instructions to the AI. If the model keeps missing the same cases, we check whether the model is weak or our request was ambiguous. Often we fix the request, and every user benefits.
  • A better repair loop. We learn which mistakes the loop fixes by itself and which it can't, and we improve the repair step where it falls short.
  • Smarter guards. Momentum checks what the AI writes before it runs. Testing shows when a guard raises a false alarm on harmless code, which would block real users, and when it correctly catches something risky. We tune it both ways.
  • Honest language support. The results show where a language works well on local models and where it is slower or less reliable, so we can say plainly what to expect.

What about AI drift?

"Drift" can mean three different things, and Momentum treats them differently.

  • Drifting away from what you asked for. This is what the design is meant to contain: programs are built and tested against your description, a failed test sends the AI back to repair it, and consent is required before changes. That is the design, and parts of it are still in preview. Even when it works it reduces drift and does not remove it, which is why our studies score results with a separate checker the AI never sees.
  • A model changing over time. Momentum cannot stop a model from changing when it is updated, but we can measure it. Our fixed tests give a recorded baseline for a pinned model, so a new model or version can be run through the same tests and compared before we recommend it.
  • Randomness between runs. Momentum's own steps run at temperature 0 to keep them steady. Our studies deliberately use a higher setting so we measure the real spread, and we repeat runs so a pass rate tells you more than one lucky result.

We don't claim Momentum prevents AI drift. What we can say today is that our own testing measures it. The workflow is designed to catch and contain it. Our drift measurements come from our own testing, not from a monitor inside the app.

Safe on your machine

Our study runs also check that the work ends cleanly: nothing is left running and every resource is released. We watch for this run after run, not just in a demo.

Why this matters to you

If you are deciding whether you need Momentum, the question is not whether an AI can write code. It can. The question is who checks the result, who repairs it, and who stops it from touching things you didn't approve. Momentum is being built as the checking, repair and consent layer around the AI, and this testing is how we keep that work honest.
