Why Momentum is tested the way it is

The problem with AI-written programs

Asking an AI to write a program is easy. Knowing the program works is the hard part. It can look right, compile, and still fail on the awkward inputs: an empty value, a stray tab, a Windows line ending. It can also quietly do something you never agreed to.

Momentum is built around that gap. You describe what you want. Momentum has an AI generate the program, build it, test it and repair it in a loop, with guards and your consent before anything changes. The loop is only worth trusting if it has been pushed hard first.

How we test it

For each language Momentum supports, we run the same kind of trial a user would trigger. A local model is given a task and writes the code, and the code is built and run. We then score it with a checker the model never sees, so it can't pass by guessing what we look for.

We repeat this many times per language, because one lucky run proves nothing. We record how often the result is right, how long it takes and how fast the model works on ordinary hardware. The exact method, briefs and terms are on How we test.

What a failure gives us

A failed trial is useful. We read why it failed and change something in Momentum:

  • Clearer instructions to the AI. If the model keeps missing the same cases, we check whether the model is weak or our request was ambiguous. Often we fix the request, and every user benefits.
  • A better repair loop. We learn which mistakes the loop fixes by itself and which it can't, and we improve the repair step where it falls short.
  • Smarter guards. Momentum checks what the AI writes before it runs. Testing shows when a guard raises a false alarm on harmless code, which would block real users, and when it correctly catches something risky. We tune it both ways.
  • Honest language support. The results show where a language works well on local models and where it is slower or less reliable, so we can say plainly what to expect.

Safe on your machine

Every study run also checks the promises Momentum makes to you: nothing is left running and every resource is released when the work ends. We watch this hold up run after run, not just in a demo.

Why this matters to you

If you are deciding whether you need Momentum, the question is not whether an AI can write code. It can. The question is who checks the result, who repairs it, and who stops it from touching things you didn't approve. Momentum is the checking, repair and consent layer around the AI. This testing is how we keep that layer honest.
