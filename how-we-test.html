How we test languages

Momentum Core 1.0 for Mac and Windows is expected in December 2026. This page explains exactly how the numbers in the language table are produced, so you can judge them or repeat the test.

The method

  1. For each language profile we give Momentum one of two small command-line briefs, alternating between them, for ten runs.
  2. Momentum writes the program, builds it, runs the tests it wrote itself and repairs failures. A run counts as passed only if it finishes within four repair rounds and also passes the separate acceptance suite described below. All ten planned runs stay in the count.
  3. That acceptance suite is a separate set of checks that Momentum did not write. Its figure is the one shown in the results table.
  4. All runs use one model (qwen3.6:27b) on our own test machine, with the test setting temperature 0.7. Momentum itself runs at 0.
  5. Labels: Recommended is 9 or 10 of 10, Works with limits is 4 to 8, Experimental is 3 or fewer. Untested models and languages say untested. A profile with no result is shown as In development and testing.

The two briefs, word for word

Brief A: Count lines, words and characters

A command-line word counter. Given a text file path, print the number of lines, words and characters, like wc. With no path, read standard input. Report a missing file with a clear error and exit code 1.

Required behaviours:

  • Count lines, words and characters of a file
  • Read standard input when no path is given
  • Report a missing file and exit 1

Brief B: Summarise a list of integers

A command-line number summary tool. Given a text file path, read one integer per line and print the count, the sum, the minimum, the maximum and the average with exactly two decimals, in that order. With no path, read standard input. Ignore empty lines. If a line is not a valid integer, report its line number with a clear error and exit with code 2. If the input holds no integers, report that and exit with code 2. Report a missing file with a clear error and exit code 1. Integers can be negative and large; the sum must not overflow for values up to 2147483647.

Required behaviours:

  • Print the count, sum, minimum, maximum and average (two decimals) of the integers in a file
  • Read standard input when no path is given
  • Ignore empty lines
  • Report a line that is not an integer, with its line number, and exit 2
  • Report input with no integers and exit 2
  • Report a missing file and exit 1

Terms used in the language table

  • Hygiene stop: an automatic scan of the programs the model writes looks for words that suggest secrets or keys. If it matches, the study stops, a person reads the matching lines (not the program) and decides whether to continue. A stop does not by itself count as a pass or a fail.
  • Allowed scanner exception: a pattern the scan flags that was reviewed in advance and judged harmless, so the run continues.
  • Retry-gate decline: our study tool refused a retry because it read the graphics processor as busy. The run ended before the model could finish repairing, so it is counted as not passed and noted.
  • Recommended: 9 or 10 of 10 passing.
  • Works with limits: 4 to 8 of 10 passing, so the language is available with that caveat. Labels are not locks.
  • Experimental: 3 or fewer of 10 passing; opt-in per language with a one-line confirmation.
  • untested: no current result for that model or language.

What we do not publish

The acceptance suite is deliberately not published. If the answer key were public, a model or a user could tune to it and it would stop telling you anything. We publish its results, not its contents. Our internal test harness is also not published, because it is not needed to repeat the briefs and contains machine-specific settings.

What these numbers are not

They are observed rates on two small briefs, one model and one machine. They are not guarantees, they say nothing about other briefs or models, and a label describes one study, not a promise.

Repeat it yourself

You can give these briefs to any setup you like and count how many of ten runs build and pass. If you want to share your numbers, tell us the model, the setting and the count. Reports from outside will be listed separately and labelled community-reported, never mixed into our figures.
